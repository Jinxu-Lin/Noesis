# Skill: Project-Level Review (项目级审查) — Phase P7

## 触发场景
P6 LaTeX 编译完成后，对**整个研究项目**（不仅是论文）进行多视角审查。

## 输入
- `Papers/latex/main.tex` — 最终论文
- `Papers/paper.md` — 完整论文 Markdown
- `Papers/review.md` — P5 终审报告
- `Papers/critique/summary.md` — P3 审查汇总
- `contribution.md` — 贡献列表
- `gap-analysis.md` — Gap 分析
- `method-design.md` — 方法设计
- `experiment-design.md` — 实验设计
- `Codes/` — 代码与实验结果（如存在）

## 执行流程

本阶段依次执行 **3 个审查角色**，每个角色产出独立报告，最后综合。

---

### Step 1: Critic 审查（攻击者视角）

以**严苛的学术批评者**身份，攻击性地寻找项目弱点。

**审查维度**：

1. **逻辑漏洞**：循环论证、因果/相关混淆、不支撑的推理跳跃
2. **方法论问题**：缺失的控制变量、混淆因子、样本量不足、p-hacking 风险
3. **Proxy Metric Gaming（关键）**：
   - Claim 的指标改进是否对应真实质量提升？
   - 是否存在退化输出（重复、不连贯）刷高指标？
   - 是否有二级指标（多样性、人类判断）交叉验证？
   - 改进幅度是否可疑（>30% 需特别审视）？
   - 检查实际生成样本，不仅看汇总统计
4. **写作问题**：模糊声明、过度声明、缺失限制条件、结构混乱
5. **新颖性评估**：贡献是否真正新颖？与最接近的 prior work 的区别
6. **可复现性**：信息是否足够让他人复现？
7. **缺失 Baselines**：哪些关键比较缺失？

**产出**：`Papers/project-review/critic.md`

```markdown
# Critic Review Report

## 总体评价
- **攻击强度**: X / 10（问题严重程度）
- **核心弱点**: （2-3句概括）

## 问题清单（按严重程度排序）

### [Critical] 问题标题
- **位置**: 论文章节 / 研究文档
- **问题**: 具体描述
- **证据**: 引用原文或数据
- **建议修复**: 具体方案

### [Major] ...

### [Minor] ...

## Proxy Metric Gaming 检查
- **检查结果**: 通过 / 存在风险
- **详细分析**: ...

## 缺失的 Baselines / Ablations
1. ...
```

### Step 2: Supervisor 审查（监督者视角）

以**独立第三方监督者**身份，进行全面质量评估。你不是研究团队成员——你是独立审查员。

**审查维度**：

1. **质量评分**：对整个项目评分（1-10），附具体理由
2. **问题识别**：错误、逻辑缺口、不支撑的声明、缺失引用
3. **改进建议**：具体、可执行的改进方案
4. **风险评估**：识别下游可能出现的问题（如提交后被审稿人质疑的点）
5. **最佳实践检查**：是否符合科学严谨性标准
6. **交叉验证**：实验声明是否与实际结果一致？

**产出**：`Papers/project-review/supervisor.md`

```markdown
# Supervisor Review Report

## 总体评价
- **项目质量评分**: X / 10
- **核心评价**: （2-3句概括）

## 分维度评分
```

### Step 3: 外部审查（可选）

如果系统配置了外部 AI MCP（如 Codex / GPT-5.4），调用外部模型进行独立第三方审查，获取不同 AI 系统的差异化视角。

**检查 MCP 可用性**：尝试调用外部 AI MCP tool。如果不可用，跳过本步骤并在 synthesis 中注明。

**外部审查要求**：
- 以独立第三方视角评审（不受 Claude 生态偏见影响）
- 指出被忽略的风险、假设漏洞、方法论缺陷
- 提供具体改进建议
- 打分 1-10 并给出理由

**产出**：`Papers/project-review/external.md`（如不可用则不生成）

---

## AI Co-Author 关键行为
- **Critic 与 Supervisor 角色分离**——即使是同一个 Agent 执行，也要严格切换视角，不要混合两种角色
- **Critic 要真正攻击**——不是走形式，要假设自己是最严苛的审稿人，目标是找到论文被拒的理由
- **Supervisor 要独立判断**——不受 Critic 结论影响，做自己的独立评估
- **Proxy Metric Gaming 是重点**——自动科研系统最容易出现指标刷分，必须认真检查
- **综合报告要有决策价值**——最终 synthesis 要给出明确的行动建议，不是简单堆砌

## 输出

- `Papers/project-review/supervisor.md` — Supervisor 审查报告
- `Papers/project-review/external.md` — 外部审查报告（可选）
- `Papers/project-review/synthesis.md` — 综合审查报告
